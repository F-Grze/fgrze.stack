<p>这篇笔记记录我最近在做的这件事：拿一个简化版的小体系（几个粒子 + 一个粗糙的势能面）当数据源，训一个图神经网络，让它同时输出下一时刻的坐标和力，然后在轨迹对比里看它到底像不像。</p>
<h2>先说清楚为什么是图</h2>
<p>分子体系的自然表示就是图：</p>
<ul>
<li><strong>节点</strong> = 原子，特征是元素种类、部分电荷、所属残基、空间位置；</li>
<li><strong>边</strong> = 原子对，作用半径 cutoff 之内连边，特征是距离、距离的径向基展开（RBF）、方向余弦；</li>
<li><strong>全局特征</strong> = 体系温度、总能量、盒子尺寸。</li>
</ul>
<p>关键在于置换等变性：两个原子互换编号，物理上不应该有任何区别。所有消息传递的层数堆得再深，也只是让每个原子的表示依赖于它的邻域，而邻域本身又被规范成度数归一化的形式。</p>

<span class="hljs-keyword">import</span> torch.nn <span class="hljs-keyword">as</span> nn

<h2>邻居列表是最容易出错的地方</h2>
<p>我在这上面踩过一次很典型的坑：推理时用的 cutoff 比训练时大 0.1 Å，误差直接翻了四倍。原因不玄学——<strong>图的边集变了</strong>。模型学到的是"在这个邻域结构下的更新规则"，你把边集换掉，等于把问题换掉了。</p>
<p>所以训练和推理必须共用同一套建图逻辑，并且这个逻辑要写在 Dataset 里，而不是散落在训练脚本里。</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">import</span> numpy <span class="hljs-keyword">as</span> np


<span class="hljs-keyword">def</span> <span class="hljs-title function_">build_neighbor_list</span>(<span class="hljs-params">positions, cutoff=<span class="hljs-number">5.0</span>, max_neighbors=<span class="hljs-number">32</span>, cell=<span class="hljs-literal">None</span></span>):
    <span class="hljs-string">"""周期性边界下的邻居列表。
    positions: [N, 3]
    返回 (edge_index, edge_vec, edge_dist, mask)
    """</span>
    n = positions.shape[<span class="hljs-number">0</span>]
    <span class="hljs-comment"># 用 cell 偏移做最小镜像约定</span>
    delta = positions[:, <span class="hljs-literal">None</span>, :] - positions[<span class="hljs-literal">None</span>, :, :]
    <span class="hljs-keyword">if</span> cell <span class="hljs-keyword">is</span> <span class="hljs-keyword">not</span> <span class="hljs-literal">None</span>:
        delta -= cell * np.<span class="hljs-built_in">round</span>(delta / cell)
    dist = np.linalg.norm(delta, axis=-<span class="hljs-number">1</span>)

    mask = (dist &#x3C; cutoff) &#x26; (dist > <span class="hljs-number">1e-6</span>)
    <span class="hljs-comment"># 屏蔽自己</span>
    np.fill_diagonal(mask, <span class="hljs-literal">False</span>)

    src, dst = np.nonzero(mask)
    vec = delta[src, dst]
    d = dist[src, dst]

    <span class="hljs-comment"># 每个节点最多保留 max_neighbors 个最近的邻居</span>
    <span class="hljs-keyword">if</span> <span class="hljs-built_in">len</span>(src) > <span class="hljs-number">0</span>:
        order = np.lexsort((d, src))
        src, dst, vec, d = src[order], dst[order], vec[order], d[order]
        counts = np.bincount(src, minlength=n)
        keep_src, keep_dst, keep_vec, keep_d = [], [], [], []
        start = <span class="hljs-number">0</span>
        <span class="hljs-keyword">for</span> c <span class="hljs-keyword">in</span> counts:
            idx = np.arange(start, start + <span class="hljs-built_in">min</span>(c, max_neighbors))
            keep_src.append(src[idx]); keep_dst.append(dst[idx])
            keep_vec.append(vec[idx]); keep_d.append(d[idx])
            start += c
        src = np.concatenate(keep_src); dst = np.concatenate(keep_dst)
        vec = np.concatenate(keep_vec); d = np.concatenate(keep_d)

    unit = vec / np.maximum(np.linalg.norm(vec, axis=-<span class="hljs-number">1</span>, keepdims=<span class="hljs-literal">True</span>), <span class="hljs-number">1e-9</span>)
    edge_index = np.stack([src, dst])
    <span class="hljs-keyword">return</span> edge_index, unit.astype(np.float32), d.astype(np.float32), mask

<h2>损失函数：力和能量要分开看</h2>
<p>坐标直接回归 MSE 会让模型学得很"懒"——它倾向于输出一个安全的平均值，因为坐标误差的尺度不可控。更好的做法是把力当成向量的梯度来监督，而能量作为标量辅助任务。</p>
<pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">force_loss</span>(<span class="hljs-params">pred_force, true_force, sigma=<span class="hljs-number">10.0</span></span>):
    <span class="hljs-string">"""力的损失：先做归一化，否则大体系会把 loss 尺度拉爆。"""</span>
    scale = sigma / (np.<span class="hljs-built_in">abs</span>(true_force).mean() + <span class="hljs-number">1e-8</span>)
    <span class="hljs-keyword">return</span> torch.mean((scale * (pred_force - true_force)) ** <span class="hljs-number">2</span>)


<span class="hljs-keyword">def</span> <span class="hljs-title function_">energy_loss</span>(<span class="hljs-params">pred_energy, true_energy</span>):
    <span class="hljs-string">"""能量的损失：按体系大小做归一化（每原子能量）。"""</span>
    <span class="hljs-keyword">return</span> torch.mean((pred_energy - true_energy) ** <span class="hljs-number">2</span>)


<span class="hljs-comment"># 训练时的总损失</span>
loss = force_loss(out.force, batch.force) + <span class="hljs-number">0.1</span> * energy_loss(out.energy, batch.energy)

<p>我的经验是：<strong>力的权重比能量重要一个数量级</strong>。能量错了模型还能凑合，力量错了轨迹就完全跑偏——因为积分器会把力误差当成速度误差直接累积。</p>
<h2>轨迹对比比逐点误差更能说明问题</h2>
<p>逐帧 RMSE 好看不代表轨迹对。真正要看的是沿时间方向的稳定性：模型会不会在某个高势垒区域"卡住"，或者在势阱里画出奇怪的圈。</p>

<h2>还没解决的问题</h2>
<ol>
<li><strong>长程相互作用</strong>：cutoff 之外的相互作用现在完全丢掉了，在长程静电显著的体系里误差积累很快。</li>
<li><strong>多保态</strong>：双阱势垒那种场景，模型很容易学出"平均行为"，把两个态之间的跃迁抹平。</li>
<li><strong>速度依赖</strong>：真正的 MD 里力还依赖速度，当前实现只有位置依赖的保守力。</li>
</ol>
<p>这些都是可以继续做的方向。先把"能跑通"的部分记下来，剩下的留到下一篇。</p>
<h2>小结</h2>
<ul>
<li>图天然契合分子体系，置换等变性靠度数归一化 + 方向消息来保；</li>
<li>邻居列表必须训练/推理共用同一份代码；</li>
<li>力的损失比能量重要得多；</li>
<li>评价要看轨迹稳定性，而不是逐点 RMSE。</li>
